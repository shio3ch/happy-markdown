# 開発と検証

## 自動検証

TypeScript・JavaScriptや依存関係を変更したら `npm run build` と `npm test` を実行します。型検査のみなら `npm run typecheck` を使用します。`npm test` は型検査・ビルド後に、`dist/` の生成物を対象として既存のCommonJSテストを実行します。対象を絞る場合も、先にビルドしてください。

```sh
npm run build
node --test test/session.test.js
```

不具合修正では可能なら回帰テストを追加し、期待する挙動を確認します。文書のみの変更は、記載内容・パス・リンク・コマンドの整合性を確認します。

React UIのテストは `test/workbench.test.js`、`test/explorer-search.test.js`、`test/explorer-ui.test.js` です。jsdom上で実際のWebviewバンドルを読み込み、CodeMirrorを維持したモード切り替え、反映待ち、競合したドラフトの復元、本文検索・目次・タスク操作、IME、古い検索応答の無視、結果のフォーカス保持、ファイルツリーの矢印キー・Home / End・文字による移動、右クリックメニュー、ブックマーク一覧を検証します。ホスト側の追従・開閉状態・永続化・世代管理は `test/explorer.test.js` で確認します。アンマウント時の実行時エラーも確認します。jsdomではCodeMirror用の計測APIを補っており、画面レイアウトとCSPの実際の適用はVS Code上で別途確認してください。

## VS Code上の確認

F5で拡張開発ホストを起動します。起動前のタスクでビルドが実行されます。`wiki` フォルダーをワークスペースとして開き、`wiki/README.md` を入口として資料を確認します。ソース変更後は再ビルドし、開発ホストを再読み込みしてください。拡張ホストのソースマップと `outFiles` を設定しているため、`src/` のTypeScriptにブレークポイントを置けます。

別のフォルダーで確認する場合は、`.vscode/launch.json` の `args` にある `${workspaceFolder}/wiki` を対象フォルダーの絶対パスに変更し、デバッグを停止してF5で起動し直します。`${workspaceFolder}/wiki/README.md` の引数は必要に応じて削除または変更してください。`--extensionDevelopmentPath=${workspaceFolder}` は開発中の拡張を読み込む指定なので、そのままにします。

デバッグは現在実行中のVS Codeを使い、一時プロファイル（`--profile-temp`）で起動します。他のインストール済み拡張は `--disable-extensions` で無効にし、開発対象のHappy Markdownは読み込みます。通常のプロファイルにある設定や拡張との干渉を切り分けるための設定です。他拡張との併用を確認するときは、この2つの引数を外して起動します。一時プロファイルの起動引数に対応していないVS Codeでは `--profile-temp` を外してください。

起動直後に終了する場合は、デバッグコンソールだけでなく、コマンドパレットの `Developer: Open Logs Folder` から `main.log` と開発ホストの `renderer.log`、`exthost/exthost.log` を確認します。`trace: true` でJavaScriptデバッガーの診断ログも有効にしています。拡張ホスト自体のクラッシュでは、デバッグコンソールや `exthost.log` にエラーが残らないことがあります。

参考: [VS Code公式ドキュメント — Testing Extensions](https://code.visualstudio.com/api/working-with-extensions/testing-extension)

- 表示変更: ライト・ダークテーマ、キーボード操作、フォーカス表示。
- エクスプローラー: 目のアイコンでの追従オン／オフと再起動後の保持、オンに戻したときの現在文書への追従、専用画面／ソース表示／分割グループ間の切り替え時の選択連動と「表示中」、親フォルダーの自動展開、エディターのフォーカス維持、非表示時にサイドバーを開かないこと、ライト・ダークでのフォルダー／文書／しおり付き文書アイコン、フォルダー開閉時のアイコン切り替えと項目数、キーボードでの開閉、更新・モード切り替え後の展開状態、上部3アイコンの切り替え、複数Markdownの本文検索と抜粋、未保存編集後の検索更新、ファイル行からのブックマーク追加・削除、再起動後の保持、検索結果・ブックマークから専用画面を開く操作。
- 編集・同期変更: 連続入力、外部編集との競合、保存・自動保存、Undo / Redo、編集とプレビューの切り替え、LF / CRLF。
- 描画変更: 専用画面と標準Markdownプレビューの影響範囲。

自動テストと実際のVS Code上の確認は区別して記録します。画面確認ができなかった場合は未確認と明記します。

### Wikiを使った確認

1. サイドバーのファイル一覧で `design`、`development`、`features` を展開します。
2. `features/viewer` を展開し、2段階のフォルダー階層とファイルの表示を確認します。
3. `features/viewer/explorer.md` などを開き、見出し・リスト・リンク・目次の表示を確認します。
4. 上部の検索アイコンからサイドバー内の検索画面へ切り替え、「ブックマーク」や「文書」を入力します。Enterなしの更新、IME確定、連続入力、一致語の強調、クリア、複数資料の結果、カードからの文書表示を確認します。一覧へ戻っても検索語が保持されることを確認します。
5. 別フォルダーの資料をブックマークに追加し、一覧から開けること・削除できることを確認します。

通常のデバッグ対象はWikiです。表・コードブロック・チェックリストなどをまとめて確認したい場合は、補助サンプルの `examples/preview.md` を開きます。
