# 開発と検証

## 自動検証

TypeScript・JavaScriptや依存関係を変更したら `npm run build` と `npm test` を実行します。型検査のみなら `npm run typecheck` を使用します。`npm test` は型検査・ビルド後に、`dist/` の生成物を対象として既存のCommonJSテストを実行します。対象を絞る場合も、先にビルドしてください。

```sh
npm run build
node --test test/session.test.js
```

不具合修正では可能なら回帰テストを追加し、期待する挙動を確認します。文書のみの変更は、記載内容・パス・リンク・コマンドの整合性を確認します。

React UIのテストは `test/workbench.test.js`、`test/explorer-search.test.js`、`test/explorer-ui.test.js` です。jsdom上で実際のWebviewバンドルを読み込み、CodeMirrorを維持したモード切り替え、反映待ち、競合したドラフトの復元、本文検索・目次・タスク操作、IME、古い検索応答の無視、結果のフォーカス保持、ファイルツリーの矢印キー・Home / End・文字による移動、右クリックメニュー、ブックマーク一覧を検証します。`test/explorer-files.test.js` は、新規作成と空フォルダー、複製時の未保存本文・CRLF・BOM、コピー・切り取り・貼り付け、衝突・キャンセル・失敗、フォルダーの名前変更、削除確認と未保存文書の保護、ワークスペース境界・不正ID・シンボリックリンクを検証します。`test/explorer-keybindings.test.js` ではOS別の `contributes.keybindings`、コマンド登録、フォーカス・選択・貼り付けのコンテキスト、連続した名前変更要求の抑止、フォーカスのコンテキスト更新が他のAPI応答を待たないこと、コピー・切り取りでワークスペースを再走査しないことを検証します。UIテストではファイル操作のキーをWebview内で処理せずVS Codeへ渡すこと、IMEと長押しの抑止、ホストからのメニュー表示・フォルダー開閉・フォーカス復帰、単クリックとダブルクリックの使い分け、選択通知の即時性、ウィンドウ復帰時の行復元、文書追従が操作中の選択を変更しないことを確認します。これらのモックではVS Code本体のキーバインド解決器を実行しないため、実機確認とは区別します。UIテストは作成ツールバー、メニュー全項目、ショートカットのVS Codeへの転送、内部ファイルのドロップと外部ドロップの拒否も確認します。ファイル操作はインメモリーのVS Code APIで検証し、実際のファイル操作のUndo / Redoとは区別します。ホスト側の追従・開閉状態・永続化・世代管理は `test/explorer.test.js` で確認します。アンマウント時の実行時エラーも確認します。jsdomではCodeMirror用の計測APIを補っており、画面レイアウトとCSPの実際の適用はVS Code上で別途確認してください。

`test/editor.test.js` はCodeMirror本体を動かし、ライブ装飾、選択行・複数行選択の記法表示、即時入力、外部更新、コード内・エスケープ記法の扱い、入力HTMLとURLの安全性、タスクの1文字だけの変更、フォーカス保持、IME中のDOM保持、保存・Undo / Redoのホスト操作、Enterによるリスト継続を確認します。実機でのIME変換やブラウザーのレイアウトとは区別してください。

同じMarkdownから編集DOMとプレビューDOMを生成し、共通CSSによる見出し1〜7・文字装飾・引用・コード・チェックボックスの書式一致、見出しの下線がないこと、明示的な水平線は残ることも確認します。jsdomではCSSの優先度・変数・実寸の計算に制約があるため、改行・余白・テーマ色の実際の見え方はVS Codeで確認します。

表の回帰テストではプレビューとのセル内容・列配置・書式の一致、セルへの直接入力とDOM・フォーカスの維持、Tab・Shift+Tab・Enter、操作メニューからの行・列の追加・削除・移動、オプションからの表全体の削除、行・見出しのホバーで対象のハンドルだけ表示すること、セル境界のフォーカス、メニューの保持・キーボード移動・古い項目の無効化、ポインターとキーボードの並べ替え、ドラッグ後の誤クリック抑止、中断・外部更新時のキャンセル、空セル・エスケープしたパイプ、IME中の入力とキャンセル、Undo / Redo・外部更新、引用・リスト内や列数が不揃いの表、コード内の除外、貼り付け・画像・URLの安全性を確認します。VS Codeでの貼り付けに必要なキーイベントの伝達も検証します。`test/workbench.test.js` では、セルの連続入力・構造変更・古い応答・削除後のUndo・競合したドラフト・モード切り替えを文書同期と組み合わせて確認します。

## VS Code上の確認

`test/mermaid.test.js` は、フローチャート・シーケンス図、テーマ変更、エラー時のコード保持、ライブ編集の記法への切り替え、古い描画の破棄、文書からの安全設定上書きの抑止を検証します。SVG計測はjsdom用に補っているため、図の配置・見切れ・CSPはVS Codeで別途確認します。Wikiの[Mermaid確認用文書](../features/viewer/mermaid.md)で両モード、ライト・ダーク、記法編集ボタンと矢印・Tab操作を確認してください。

Mermaid内部の一時DOM生成・サニタイズでは、インラインスタイルを既存CSPが遮断するため開発者ログに警告が出ます。最終SVGには許可したスタイルだけをCSSOM・nonce経由で適用します。実画面では文字の中央揃えと図の寸法も確認してください。警告を消す目的でCSPに `unsafe-inline` を追加しないでください。

F5で拡張開発ホストを起動します。起動前のタスクでビルドが実行されます。`wiki` フォルダーをワークスペースとして開き、`wiki/README.md` を入口として資料を確認します。ソース変更後は再ビルドし、開発ホストを再読み込みしてください。拡張ホストのソースマップと `outFiles` を設定しているため、`src/extension/` のTypeScriptにブレークポイントを置けます。

別のフォルダーで確認する場合は、`.vscode/launch.json` の `args` にある `${workspaceFolder}/wiki` を対象フォルダーの絶対パスに変更し、デバッグを停止してF5で起動し直します。`${workspaceFolder}/wiki/README.md` の引数は必要に応じて削除または変更してください。`--extensionDevelopmentPath=${workspaceFolder}` は開発中の拡張を読み込む指定なので、そのままにします。

デバッグは現在実行中のVS Codeを使い、一時プロファイル（`--profile-temp`）で起動します。他のインストール済み拡張は `--disable-extensions` で無効にし、開発対象のHappy Markdownは読み込みます。通常のプロファイルにある設定や拡張との干渉を切り分けるための設定です。他拡張との併用を確認するときは、この2つの引数を外して起動します。一時プロファイルの起動引数に対応していないVS Codeでは `--profile-temp` を外してください。

起動直後に終了する場合は、デバッグコンソールだけでなく、コマンドパレットの `Developer: Open Logs Folder` から `main.log` と開発ホストの `renderer.log`、`exthost/exthost.log` を確認します。`trace: true` でJavaScriptデバッガーの診断ログも有効にしています。拡張ホスト自体のクラッシュでは、デバッグコンソールや `exthost.log` にエラーが残らないことがあります。

参考: [VS Code公式ドキュメント — Testing Extensions](https://code.visualstudio.com/api/working-with-extensions/testing-extension)

自動テストと実際のVS Code上の確認は区別して記録します。画面確認ができなかった場合は未確認と明記します。

### Wikiを使った確認

1. サイドバーのファイル一覧で `design`、`development`、`features` を展開します。
2. `features/viewer` を展開し、2段階のフォルダー階層とファイルの表示を確認します。
3. `features/viewer/explorer.md` などを開き、見出し・リスト・リンク・目次の表示を確認します。
4. 上部の検索アイコンからサイドバー内の検索画面へ切り替え、「ブックマーク」や「文書」を入力します。Enterなしの更新、IME確定、連続入力、一致語の強調、クリア、複数資料の結果、カードからの文書表示を確認します。一覧へ戻っても検索語が保持されることを確認します。
5. 別フォルダーの資料をブックマークに追加し、一覧から開けること・削除できることを確認します。
6. ファイルツリーへTabで移動し、上下左右の矢印、Home / End、文字入力による移動を確認します。ファイル行のShift+F10または右クリックで操作メニューを開き、Escapeで閉じたときに行へフォーカスが戻ることを確認します。
7. 検索結果やファイル行のブックマーク操作へフォーカスを置き、状態更新後もフォーカスが保持されることを確認します。専用画面では、編集・プレビューの切り替えでカーソルと未保存の入力が保たれることを確認します。

8. 検証用の空フォルダーとMarkdownを上部ボタンから作成し、右クリックから通常タブ表示・複製・コピー／切り取りと貼り付け・絶対／相対パスコピー・名前変更・削除を確認します。フォルダーと空白部分へのドラッグ、同名衝突、キャンセル、切り取り状態と、Shift+F10・上下キー・Home / End・Escape・名前変更（macOSはEnter、Windows／LinuxはF2）・削除（macOSは⌘Backspace）・Ctrl / Cmd+C／X／Vも確認します。Spaceでサイドバーにフォーカスを残す表示、通常タブ表示（macOSは⌘↓、Windows／LinuxはEnter）、Ctrl+Enterで横に開く操作とOS別のパスコピーも確認します。
9. 検証用文書を未保存で編集し、移動・名前変更後も入力・保存・Undo / Redo・モード切り替えを確認します。未保存文書を含むフォルダーの削除は拒否されること、ファイル操作のUndo / Redoでブックマークも追従することを確認します。フォルダー作成のUndoは対象外です。
10. 一時プロファイルで、既定の名前変更キーを解除し、`happyMarkdown.explorer.rename` にF9などの別キーを割り当てます。既定キーが反応しなくなり、新しいキーだけでダイアログが開くこと、検索入力中には誤作動しないことを確認します。確認後は一時設定を破棄します。独自メニューの表示が「既定」と明記されることも確認します。
11. ファイルを1回クリックし、エディターへフォーカスが移らずCtrl / Cmd+Cが使えることを確認します。フォルダーからファイル、別のファイルへの切り替え直後にもコピー対象が正しいこと、ダブルクリック／通常タブを開くキーではエディターへ移ること、ツリーへ戻った後に選択行とコピーが復元されることを確認します。検索欄・ソース表示・ブックマークなどのボタンにはフォーカスを奪い返さないことも確認します。
12. ライト・ダーク、狭いサイドバー、長いファイル名、画面下端のメニューで見切れとスクロール、フォーカス表示を確認します。検証用のファイル・フォルダーは確認後に削除します。

確認のために変更したブックマーク・文書追従の設定・テーマは、確認前の状態へ戻します。文書を編集して保存・Undo / Redoを確認する場合も、検証用の変更を残さないようにします。

通常のデバッグ対象はWikiです。表・コードブロック・チェックリストなどをまとめて確認したい場合は、補助サンプルの `examples/preview.md` を開きます。
