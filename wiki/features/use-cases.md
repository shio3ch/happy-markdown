# できること一覧 — ユースケース

Happy Markdownで現在できることを、利用者の目的から探すための一覧です。各行の「したいこと」に対して、操作と得られる結果をまとめています。

この資料では、実装済み機能の使い道を説明するためにユースケース形式を採用します。「誰が・何を・なぜしたいか」を中心に開発の目的を整理するユーザーストーリー形式より、現在の操作と結果を案内しやすいと考えています。

## 利用の前提

- VS CodeでMarkdownを含むフォルダー、または複数フォルダーのワークスペースを開きます。
- サイドバーのHappy Markdownから文書を選ぶと、専用画面で開きます。既に標準エディターで開いているMarkdownは、コマンド「Happy Markdown: 専用画面を開く」からも開けます。
- 以下は原則として専用画面とHappy Markdownのサイドバーの機能です。VS Code標準Markdownプレビューには共通CSSを適用しますが、専用画面の編集・検索・目次などを追加するものではありません。
- 「実装済み」はすべての環境での手動検証済みを意味しません。検証方法は[開発と検証](../development/testing.md)を参照してください。

## 文書を探す・整理する

| ID | したいこと | 操作と得られる結果 |
| --- | --- | --- |
| UC-01 | フォルダーをたどって文書を開きたい | ファイル一覧でフォルダーを展開し、Markdownを選びます。専用画面で文書を表示します。フォルダーの開閉アイコンと直下の項目数で構造を把握できます。 |
| UC-02 | 複数の資料フォルダーをまとめて見たい | 複数フォルダーのワークスペースを開くと、ルートごとにMarkdownを階層表示します。 |
| UC-03 | ファイル名を覚えていない文書を内容から探したい | サイドバー上部の検索アイコンに切り替え、検索欄へ言葉を入力します。全Markdownから一致ファイルを絞り込みます。Enterや検索ボタンは不要です。 |
| UC-04 | 検索した文書が目的のものか、開く前に確かめたい | 結果カードのファイル名・相対パス・一致行数・最大3行の本文抜粋を見ます。抜粋内の一致語を強調表示します。 |
| UC-05 | 検索から文書を開き、別の文書も続けて探したい | 結果カードから専用画面を開きます。一覧・ブックマークと画面を切り替えても検索語を保持します。クリアボタンで検索語と結果を消せます。 |
| UC-06 | よく読む資料へすぐ戻りたい | 一覧のファイル行、右クリックメニュー、または検索結果からブックマークに追加します。上部のブックマーク画面から開け、登録はワークスペース単位で保持します。解除もできます。 |
| UC-07 | 開いている文書がフォルダーのどこにあるか知りたい | 文書への追従がオンなら、タブ・エディターグループの切り替えに合わせて一覧の対象行を選択し、親フォルダーを展開します。検索では対象カードを枠線と「表示中」で示します。 |
| UC-08 | 読む文書を切り替えても一覧を動かしたくない | 上部右端の目のアイコンで文書への追従をオフにします。自動選択・自動展開・「表示中」を停止し、設定をワークスペース単位で保持します。 |
| UC-09 | 一覧を最新のファイル構成に合わせたい | ファイルの追加・削除・名前変更には自動で追従します。上部の更新アイコンで手動更新もできます。 |
| UC-10 | Markdownのソースを標準エディターで確認したい | ファイル行のソース操作、または検索結果の「ソースを開く」を使います。VS Code標準テキストエディターで同じ文書を開きます。 |

検索対象は一覧と同じMarkdownです。`node_modules`、`.git`、`.cache` は除外します。検索は大文字・小文字を区別しない文字列検索で、未保存の文書内容も対象にします。詳細は[エクスプローラー](viewer/explorer.md)を参照してください。

## 文書を書く・整える

| ID | したいこと | 操作と得られる結果 |
| --- | --- | --- |
| UC-17 | 文書を編集して、仕上がりも確認したい | 専用画面の「編集する」「プレビュー」で切り替えます。編集はMarkdownテキストとして行い、未保存の入力と編集カーソルを保持して切り替えます。 |
| UC-18 | 記法を覚えずに文章を装飾したい | 編集ツールバーから見出し・太字・斜体・下線・取り消し線・インラインコードを挿入します。選択した文章への適用もできます。 |
| UC-19 | 箇条書きや引用をまとめて整えたい | 対象行または複数行を選択してリスト・引用を適用します。番号付きリストは1から連番にし、水平線も挿入できます。 |
| UC-20 | リンク・表・コードブロックのひな形を入れたい | 編集ツールバーからひな形を挿入し、内容を入力します。コードブロックでは選択済みの文章をコードとして取り込めます。 |
| UC-21 | 画像を文書へ追加したい | ファイル選択またはURLの入力で画像記法を挿入します。文書フォルダー内の画像は相対パスで参照し、外の画像は文書横の `assets` にコピーします。元画像は変更しません。 |
| UC-22 | 編集中のテキスト内を検索したい | 編集画面の検索パネルを使います。プレビュー内検索、サイドバーの全文検索とは対象の画面が異なります。 |

編集はWYSIWYGではありません。見出し7は専用画面の拡張記法、下線はHTMLの `<u>` を使います。画像ファイルの追加前にはMarkdownを保存しておく必要があります。画像のコピー自体はUndoで削除されません。詳細は[編集機能](editing.md)を参照してください。

## 変更を保存する・やり直す

| ID | したいこと | 操作と得られる結果 |
| --- | --- | --- |
| UC-23 | 専用画面での変更をファイルへ保存したい | 保存ボタンまたは保存ショートカットを使います。編集はVS Codeの文書へ反映し、ファイル保存は通常の保存・自動保存設定に従います。プレビューのチェック操作も同じ文書に反映します。 |
| UC-24 | 編集を取り消したり、取り消した操作を戻したい | 編集ツールバーまたはショートカットでUndo / Redoを使います。VS Codeの文書履歴と連携します。 |
| UC-25 | 別の場所で文書が変わったとき、入力を失わずに対応したい | 入力中の変更と外部更新が競合した場合は、入力を保持して競合を表示します。「最新の文書を読み込む」か「入力中の内容を反映」を利用者が選びます。変更の反映に失敗した場合も入力を保持します。 |

競合解決の「入力中の内容を反映」は、自動マージではなく保持した入力による置換です。選択前に内容を確認してください。同期の詳細は[文書同期](../design/document-sync.md)を参照してください。

## 代表的な使い方の流れ

### 内容を手掛かりに資料を探して読む

1. ワークスペースを開き、Happy Markdownの検索画面へ切り替えます。
2. 覚えている言葉を入力します。結果カードのパスと抜粋から目的の資料を選びます。
3. カードを押して専用画面で読みます。文書内をさらに探す場合は、プレビュー上部の検索や目次を使います。
4. 再び読む資料なら、検索結果またはファイル一覧からブックマークに登録します。

結果がない場合は検索語を変更します。本文検索は文字列一致なので、単語の揺れや別表記を自動で補完しません。読み込めないファイルがあれば、検索結果の件数表示にその数を添えます。

### 資料を修正して保存する

1. 文書を専用画面で開き、「編集する」に切り替えます。
2. Markdownを入力し、必要に応じてツールバーで装飾や表・画像を挿入します。
3. プレビューへ切り替えて表示を確認します。
4. 保存します。外部更新との競合が表示された場合は、保持された入力と最新文書のどちらを採用するか選びます。

## 今はできないこと

- フロントマターのキー・値、タグなどを検索条件として指定すること。
- サイドバー検索での正規表現の指定や、検索結果から一致箇所への自動スクロール。
- ブックマークしたファイルの名前変更に合わせて、登録パスを自動で変更すること。
- WYSIWYG編集、Mermaidの描画、他拡張の描画機能の継承。

これらは上の実装済みユースケースには含めません。その他の制約は[現在の仕様と未対応の範囲](limitations.md)を参照してください。
