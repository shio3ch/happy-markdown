# Markdownエクスプローラー

ファイル一覧・本文検索・ブックマークを、1つのWebview内のReactコンポーネントとして表示します。Markdownとフォルダーを階層表示し、空のフォルダーも表示します。複数フォルダーのワークスペースに対応し、ファイルの追加・削除・名前変更に追従します。`node_modules`、`.git`、`.cache` は対象外です。VS Code標準エディターでソースを開く経路も備えています。

フォルダーは開閉状態に合わせて専用アイコンを切り替え、直下の項目数を表示します。文書は青系のページアイコン、ブックマーク済み文書はしおり付きのページアイコンで区別します。ライト・ダーク用のSVGを同梱し、ファイルアイコンテーマに依存せず表示します。フォルダー行の矢印から展開・折りたたみを操作でき、一覧更新・モード切り替えでもフォルダーの展開状態を保持します（VS Code再起動後の保持は対象外）。

現在アクティブなMarkdown文書は行に「表示中」を添え、選択表示します。専用画面・標準テキストエディターのタブ切り替えとエディターグループの切り替えに追従し、ファイル一覧では必要な親フォルダーを展開します。フォーカスはエディターに残し、非表示のエクスプローラーを自動で開きません。ブックマークでは対象文書が現在の一覧に含まれる場合のみ選択します。検索画面では一致した文書のカードを枠線と「表示中」で示します。行選択はツリー操作でも変わりますが、「表示中」はアクティブな文書を示します。ツリーにキーボードフォーカスがある間は、遅れて届いた文書追従で選択中の操作対象を変更しません。

文書への追従は、上部右端の目のアイコンでオン／オフを切り替えます。初期状態はオンで、ワークスペースごとに保存します。オフでは自動選択・自動展開と「表示中」の表示を停止し、オンに戻すと現在の文書に追従します。通常のクリックによる行選択は利用できます。

Webview内上部のアイコンは左からファイル一覧、本文検索、ブックマークです。右側に一覧の更新アイコンがあります。ビューの説明に現在のモードを表示します。表示切り替え・更新・文書追従、新規作成・貼り付け、行内のソース表示・ブックマーク、検索欄のクリアの各操作アイコンは、約350msのホバーまたはキーボードフォーカスで説明を表示します。貼り付けが無効な場合は理由も表示します。説明は画面内に収まる位置へ配置し、ポインターが離れる・フォーカスが外れる・クリック・Escapeで閉じます。

- 本文検索: 上部の検索アイコンで、同じサイドバー内の検索画面へ切り替えます。入力欄は画面内に常設し、入力後約100msで検索を開始します。検索ボタンやEnterによる確定は不要です。日本語の変換中は待ち、変換確定後に更新します。ワークスペース内の全Markdown（一覧と同じ拡張子・除外条件）を、大文字・小文字を区別しない文字列検索で調べます。正規表現は使いません。未保存のTextDocumentも対象です。
- 検索結果: ファイル名・相対パス・一致した行数と最大3行の本文抜粋をカードに表示し、抜粋内の最初の一致語を強調します。長い行では一致箇所付近を抜粋します。カードを押すと専用画面を開きます（一致箇所への自動スクロールは未対応）。カード下部からブックマークの追加・解除、ソース表示も利用できます。
- 検索状態: ファイル一覧・ブックマークへ切り替えても検索語を保持します。クリアボタンで検索語と結果を消去します。ファイル変更・文書編集時は検索結果を更新し、古い検索の完了結果で新しい検索語の結果を上書きしません。
- ブックマーク: ファイル行のアイコンまたは右クリックメニューから追加・削除します。ワークスペース単位で保存し、VS Codeを開き直しても保持します。ブックマーク画面から専用画面を開けます。削除・名前変更で存在しなくなったパスは表示しません。このエクスプローラーの移動・名前変更、およびVS Codeのファイル操作による名前変更では登録パスも更新します。外部ツールによる名前変更の追跡は対象外です。

検索結果とブックマークには相対パスを表示し、別フォルダーの同名ファイルを区別します。

検索条件と検索処理は画面から分離しています。現在の条件は本文の文字列のみです。フロントマターのキー・値などによる絞り込みは今後の拡張対象で、未実装です。

## ファイル・フォルダーの操作

ファイル行を1回クリックすると、専用画面のプレビュータブで表示し、フォーカスはツリーに残します。そのままコピー・切り取りや矢印キーでの移動を続けられます。ダブルクリックでは通常タブで開いてエディターへフォーカスを移します。キーボードの「通常タブで開く」やメニューの明示的な「開く」操作もエディターへ移り、Spaceはツリーにフォーカスを残します。エディターや別ウィンドウから戻ると、最後に操作していたツリー行を復元します。検索欄・ツールバーボタンへ移動した場合は、そのフォーカスを優先します。

一覧上部のファイル＋／フォルダー＋から新規作成します。選択中のフォルダー、または選択中のファイルと同じ階層が作成先です。何も選択していない場合はワークスペース直下へ作成し、複数ルートでは作成先を選びます。空白部分をクリックすると選択を解除できます。ファイル名には `.md` または `.markdown` を指定し、作成後は専用画面を開きます。新規フォルダーの作成は `workspace.fs.createDirectory` を使い、Undoの対象外です。

ファイル行をドラッグし、移動先フォルダーへドロップすると移動します。一覧末尾の空白部分へドロップするとワークスペース直下へ移動し、複数ルートでは移動先を選びます。移動先を枠と背景色で示します。フォルダー自体のドラッグ、外部アプリからのドロップは対象外です。

ファイル行の右クリックメニューには次の操作があります。

| 操作 | 結果 |
| --- | --- |
| ファイルを開く | 専用画面のプレビュータブで開く |
| 新規タブでファイルを開く | プレビュータブとして置き換えられない通常のタブで開く。同じ文書が既に開いている場合はそのタブを利用する |
| 複製の作成 | 同じ階層へ「名前 のコピー.md」を作成。重複時は「(2)」以降の連番。TextDocumentの未保存本文も反映する |
| コピー／切り取り | システムのテキストクリップボードへパスを入れ、拡張内で複製／移動する対象として保持する。切り取り行は薄く表示する |
| 貼り付け | コピーしたファイルを複製、または切り取ったファイルを移動する。ファイル行では同じ階層、フォルダー行ではその配下へ貼り付ける |
| パスのコピー／相対パスのコピー | 絶対パス／ワークスペースからの相対パスをテキストとしてコピー。複数ルートの相対パスにはルート名を付ける |
| 名前の変更 | 同じ階層で名前を変更する |
| 削除 | 確認ダイアログを経て削除する。未保存文書を含む場合は保存を案内して中止する |

ソース表示・ブックマークの操作もメニュー末尾にあります。フォルダー行には新規作成・貼り付け・パスのコピー・名前変更・削除を用意し、空白部分には新規作成・貼り付けを用意します。ワークスペースのルート自体は名前変更・削除できません。フォルダー削除はMarkdown以外の内容も含むため、確認ダイアログにその旨を表示します。

コピー・切り取り・貼り付けは、この拡張の同じウィンドウ内で利用します。FinderやWindows Explorerとのファイル形式でのクリップボード共有は対象外です。システムのクリップボードが別のテキストに変わっていた場合は、貼り付けを実行せず内部の対象を解除します。コピーを同名の場所へ貼り付けると連番の複製を作り、切り取り・移動・名前変更・新規作成では同名項目を上書きしません。失敗・キャンセルでは切り取り元を削除しません。

ファイルの作成・複製・名前変更・移動・削除はVS Codeの `WorkspaceEdit` を使用します。削除は独自のごみ箱操作ではなく、VS Codeのファイル操作として扱います。ワークスペース外、除外フォルダー、シンボリックリンク経由の操作は受け付けません。標準Markdownプレビューの表示には影響しません。

## キーボード操作

ファイル一覧・ブックマークのツリーにフォーカスがあるときに利用できます。検索欄や行内の操作ボタンでは、入力・ボタン本来のキー操作を優先します。Tabでツリーへ入り、上下矢印で移動、右矢印で展開／最初の子へ移動、左矢印で折りたたみ／親へ移動します。Home / Endと先頭文字による移動も利用できます。空の一覧もTabでフォーカスできます。

| 操作 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 名前変更 | Enter | F2 | F2 |
| 通常タブで開く・エディターへフォーカス | ⌘↓ | Enter | Enter |
| サイドバーにフォーカスを残してファイルを表示 | Space | Space | Space |
| 横に開く | Ctrl+Enter | Ctrl+Enter | Ctrl+Enter |
| コピー／切り取り／貼り付け | ⌘C／⌘X／⌘V | Ctrl+C／Ctrl+X／Ctrl+V | Ctrl+C／Ctrl+X／Ctrl+V |
| 削除の確認 | ⌘Backspace、Delete | Delete | Delete |
| パスのコピー | ⌘⌥C | Shift+Alt+C | Ctrl+Alt+C |
| 相対パスのコピー | ⌘⌥⇧C | Ctrl+K → Ctrl+Shift+C | Ctrl+Alt+Shift+C |
| 切り取り解除 | Escape | Escape | Escape |
| コンテキストメニュー | Shift+F10 | Shift+F10 | Shift+F10 |

macOSのEnterはフォルダーも名前変更の対象です。Windows／LinuxのEnterはフォルダーを開閉します。コピー・切り取り・表示・横に開く操作はファイルが対象です。ワークスペースのルート自体は名前変更・削除できません。名前変更の入力欄では拡張子の前までを選択し、変更・キャンセル後や削除後にはツリーへフォーカスを戻します。

メニュー内では上下矢印・Home / Endで項目を選び、Escapeで行へ戻ります。メニューと貼り付けのツールチップにはOS別の「既定」キーを表示します。IME変換中の操作、キーの長押しによる操作ダイアログの重複は抑止します。

キー割り当ては[VS Code公式のファイル操作実装](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/files/browser/fileActions.contribution.ts)と[ファイルを開く・パスをコピーする実装](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/files/browser/fileCommands.ts)を参考にしています。削除は従来のWorkspaceEditと確認ダイアログを使います。Shift+Deleteなどの完全削除用のキー、複数選択、フォルダーのコピー・切り取りは対象外です。Ctrl / Cmd+NはVS Code標準の未保存文書の新規作成として残します。

### 新規作成などにキーを割り当てる

VS Code標準で既定キーがない新規ファイル・フォルダー作成や複製は、既定キーを追加せず、コマンドを提供します。キーボードショートカット設定で「Happy Markdown: エクスプローラーで…」を検索して割り当てられます。`happyMarkdown.explorer.newFile`、`newFolder`、`duplicate`、`copy`、`cut`、`paste`、`copyPath`、`copyRelativePath`、`rename`、`delete`、`openTab`、`openSide`、`openPreview`、`cancelCut`、`contextMenu`、`toggleFolder` が対象です（後続の名前にも `happyMarkdown.explorer.` を付けます）。既存の表示切り替え・ブックマーク・更新・追従のコマンドもキーを設定できます。

ファイル操作コマンドは、表示中のこのエクスプローラーで選択した項目に適用します。既定のキーはすべて `package.json` の `contributes.keybindings` に登録し、VS Codeのキーバインド解決器から `commands.registerCommand` の処理へ渡します。Webview内にファイル操作のキー判定はありません。選択IDはフォーカスの有効化より先に同期通知します。フォーカス・選択・ルート項目・貼り付け可否・処理中の状態は `setContext` で共有し、`when` 条件で限定します。ユーザー設定でキーの変更、既定キーの解除、連続キーの割り当てができます。VS Code標準エクスプローラーの同名操作とは別コマンドなので、設定変更は `happyMarkdown.explorer.*` に対して行います。

独自の割り当てにも `happyMarkdown.explorerTreeFocus` の条件を付けるとツリー内に限定できます。公開APIでは現在の割り当てを照会できないため、独自メニューとツールチップは変更後のキーを推測せず「既定」と表示します。実際のキーはVS Codeのキーボードショートカット設定で確認してください。コピー・切り取り・パスコピー・切り取り解除では一覧を再取得せず、クリップボードの状態だけを表示へ反映します。上下左右・Home / End・先頭文字による移動と、開いたメニュー内のフォーカス操作は、カスタムWebviewのUI処理として残します。

参考: [VS Code公式 — contributes.keybindings](https://code.visualstudio.com/api/references/contribution-points#contributes.keybindings)、[when条件とsetContext](https://code.visualstudio.com/api/references/when-clause-contexts)、[コマンドAPI](https://code.visualstudio.com/api/references/vscode-api#commands)。

ツリーのロールと移動操作は[W3CのTree View Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)を参考にしています。
